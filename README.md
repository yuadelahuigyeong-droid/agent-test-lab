# Agent Test Lab

React、Express、Playwrightを使用した、顧客検索・データ検証・E2Eテストの学習用プロジェクトです。

検索処理と検証処理を分離し、HTTP通信によるサービス間連携と、正常系・異常系の自動テストを実装しています。

## 1. プロジェクトの目的

- ReactとExpressによるWebアプリケーションの構築
- 検索処理と検証処理の責務分離
- HTTP通信によるサービス間連携の実装
- エラー発生時の処理と実行ログの可視化
- PlaywrightによるE2Eテストの自動化

## 2. システム構成

```text
React (Port 5173)
    |
    v
Express API (Port 3001)
    |
    +-- Search Agent
    |      顧客データの検索
    |
    +-- HTTP POST
           |
           v
       Validator Server (Port 3002)
           |
           +-- Validator Agent
                  顧客データの検証
```

※ 現時点のSearch AgentとValidator Agentは、ルールベースの処理モジュールです。LLMによる自律的な判断や、公式A2Aプロトコルは実装していません。

開発時のブラウザからの `/api` リクエストは、Viteの開発用プロキシを介してExpress APIへ転送します（[設定](vite.config.ts)）。Search AgentはAPI内のモジュールであり、Validator Serverは別プロセスです。

この構成では、検索と検証を別の責務として扱い、HTTPによる連携を学習できます。別プロセスへの通信に伴い、接続失敗や応答エラーへの対応が必要になります。

## 3. 主な機能

### 顧客検索

顧客名を入力し、該当する顧客データを検索します。

- データは[Search Agent](server/agents/searchAgent.js)内の固定データ3件で、DBは使用していません。
- 入力の前後の空白を除去して、顧客名の部分一致で検索します。
- 空文字での検索は全件に一致します。これは実装から確認した挙動であり、専用の自動テストはありません。

### データ検証

検索結果をValidator ServerへHTTP POSTで送信し、顧客データの形式を検証します。

[Validator Agent](server/agents/validatorAgent.js)は、配列であることと、各要素の `id`・`name` が空でない文字列であることを判定します。IDの書式・重複や業務上の妥当性は検証していません。空配列は検証成功になります。

### 実行ログ表示

検索処理・検証処理の実行状況をReact画面に表示します。

### エラーハンドリング

Validator Serverとの通信に失敗した場合、HTTP 502を返し、画面にエラーメッセージと実行ログを表示します。

[API実装](server/index.js)では、Validatorの応答が成功ステータスでない場合や、JSONの読み取りで例外が発生した場合も502を返します。応答の `isValid` が `true` でない場合は500を返します。500の分岐は実装にありますが、現在の自動テストでは検証していません。

## 5. 起動方法

Node.jsとnpmがインストールされている環境で実行します。

検証時のNode.js・npm・OSのバージョンは検証記録に残していないため、動作確認済みのバージョンはここでは提示していません。依存関係は [package.json](package.json) と [package-lock.json](package-lock.json) を参照してください。

### 依存パッケージのインストール

```bash
npm install
```

### Validator Serverの起動

```bash
node server/validatorServer.js
```

### Express APIの起動

別のターミナルで実行します。

```bash
node server/index.js
```

### Reactの起動

さらに別のターミナルで実行します。

```bash
npm run dev
```

ブラウザで http://localhost:5173/ にアクセスします。

テストはこのURLを使用します。5173・3001・3002の各ポートを使用できる状態で、3つのプロセスを起動してください。ここに記載した接続経路はViteの開発サーバー用です。

## 6. テスト方法

Playwright用Chromiumをインストールします。

```bash
npx playwright install chromium
```

第5節の3サービスを起動した状態で、テストを実行します。正常系・0件検索は実際のAPIとValidator Serverを使用します。

```bash
npx playwright test
```

### テストケース

| テスト | 内容 | 通信の範囲 |
| ------ | ---- | ---------- |
| 正常系 | 顧客検索結果と成功ログを確認（検証項目はファイルごとに異なる） | 実API・Validator Serverを使用 |
| 検索結果0件 | 検索後の0件ログと結果なしの表示を確認 | 実API・Validator Serverを使用 |
| HTTP 502 | エラーメッセージと通信エラーログを確認 | 検索APIの応答をモック |

HTTP 502の自動テストでは、Playwrightの `page.route()` で検索APIのレスポンスを置き換え、画面側のエラー処理を確認しています。ExpressからValidatorへの通信や、APIが実際に502を返す処理は、このモックでは検証していません。

従来のREADMEにはValidator Serverの停止・復旧を手動確認した旨の記載がありましたが、実行日・手順・結果の詳細記録はありません。この確認を再現するには、手順と結果を改めて記録する必要があります。

2026-10-25のソース確認では、`tests/` 内の `.spec.ts` に計8件のテスト定義があります。同じシナリオを生成方法別に検証しているため、8種類の機能を網羅する意味ではありません。

### 全テストの検証結果（2026年10月25日）

React（5173）・Express API（3001）・Validator Server（3002）のHTTP応答を確認後、Playwright MCPの `test_run` を対象指定なしで実行しました。

| 項目 | 結果 |
| ---- | ---- |
| 実行ツール | Playwright MCP `test_run` |
| 対象 | 全8件（6ファイル） |
| 実行結果 | **8 passed（全8件成功）** |
| 全体実行時間 | **3.6秒** |
| 失敗 | なし |

正常検索・0件検索は実APIとValidator Serverを使用しています。HTTP 502の2件（`validator-error.spec.ts` と `spec-based.spec.ts` のTC-03）は `page.route()` によるモックを使用し、画面のエラー表示とログを確認しました。実際のValidator Server障害や、APIが502を返す処理を検証した結果ではありません。
